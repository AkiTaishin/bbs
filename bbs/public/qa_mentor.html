研修の進め方

この掲示板研修の目的は何ですか？

本研修は、Webアプリケーション開発の一連の流れを体験することを目的としています。具体的には、HTML / CSS / JavaScript によるフロントエンド、Node.js + Express によるバックエンド API、SQL Server（SSMS） によるデータ永続化という3層構造を、実際に動く掲示板アプリを通じて学びます。

研修生は index.html・script.js・server.js などのひな形ファイルを編集し、機能を追加・改善していきます。メンター用の *_bk ファイル（模範解答）と比較しながら進めることで、「何が足りないか」「どう実装すればよいか」を自分で気づける力を養います。

メンター向けヒント：最初に start_bk.bat で完成版を動かし、研修生に「最終的にこうなる」イメージを見せてから、ひな形版（start.bat）に戻すとモチベーションが上がります。

研修の推奨スケジュール（1週間想定）は？

以下は標準的な5日間の進め方の例です。研修生のスキルに応じて前後させてください。

  1. Day 1： 環境構築（Node.js、SQL Server Express、SSMS）、start.bat で起動確認、SSMS で BbsDB / Posts テーブルを目視確認
  2. Day 2： HTML / CSS の構造理解、レイアウト改善、文字数カウンターやバリデーションの追加
  3. Day 3： JavaScript の fetch 通信、投稿一覧の表示改善、エラーハンドリング
  4. Day 4： server.js の API 理解、検索・削除・リアクションなど機能追加（server_bk.js を参考に）
  5. Day 5： セキュリティ対策（SQLインジェクション、XSS、レート制限）の学習、自由課題・発表
環境構築でつまずく研修生が多いため、Day 1 は半日〜1日かけても問題ありません。check_sql_env.bat の結果を一緒に読み解く時間を確保しましょう。

研修生用ファイルとメンター用（_bk）ファイルの違いは？

プロジェクトには対になる2セットのファイルがあります。

  • 研修生用： index.html、style.css、script.js、server.js、start.bat — 機能が最小限のひな形
  • メンター用（模範解答）： index_bk.html、style_bk.css、script_bk.js、server_bk.js、start_bk.bat — 検索・リアクション・ダークモード・セキュリティ対策など完成版

研修生には *_bk ファイルを「答え合わせ用」として見せますが、最初からコピペして終わりにしないよう指導してください。「なぜこのコードが必要か」を説明できることがゴールです。

研修生が server_bk.js をそのまま server.js に上書きして提出するケースがあります。差分を口頭で説明させる、または自分で1機能ずつ移植する課題にすると学習効果が高まります。

メンターはどのタイミングで助ければよいですか？

基本方針は「15〜20分自力で試してから質問」です。ただし以下の場合は即座に介入してください。

  • start.bat 実行時に SQL Server 接続エラーが出続けている（環境問題は自力解決が困難）
  • 同じエラーを3回以上繰り返している（根本原因の特定が必要）
  • コマンドプロンプトを閉じてしまいサーバーが止まっているのに気づいていない

コードの書き方を聞かれた場合は、答えを直接書かず「どのファイルのどの関数を調べたか」「ブラウザの開発者ツール（F12）の Console / Network タブに何が出ているか」を先に確認させてください。

「エラーメッセージをそのまま読み上げる」より「エラーの最初の1行と、直前に何をしたか」を聞くと状況把握が早いです。

研修の成果物（ゴール）は何ですか？

最低限のゴールは以下です。

  1. start.bat で掲示板が起動し、投稿の閲覧・新規投稿ができる
  2. SSMS で BbsDB の Posts テーブルにデータが保存されていることを確認できる
  3. 追加した機能（検索、削除、リアクション等）について、自分の言葉で説明できる

上級ゴールとして、server_bk.js にあるセキュリティ対策（パラメータ化クエリ、XSS エスケープ、レート制限）のうち1つ以上を自分で実装し、なぜ必要かを説明できることです。

ペアプログラミングやコードレビューはどう行いますか？

推奨フローは次のとおりです。

  • 実装前： 研修生に「何を変えるか」を口頭で説明させる（設計の言語化）
  • 実装中： メンターは隣で見守り、質問が来たらヒントのみ提供（行番号や関数名の指示は OK、全文コピペは NG）
  • 実装後： index_bk.html との差分を一緒に確認し、動作テスト（正常系・異常系）を実施

レビュー時は「動くか」だけでなく「他のユーザーが悪意ある入力をしたらどうなるか」も確認すると、セキュリティ意識が育ちます。

研修生が前の経験（他言語・他フレームワーク）を持っている場合の進め方は？

経験者には「このプロジェクトでの用語の対応関係」を早めに示すとスムーズです。例：Rails の Model → SQL Server のテーブル、Controller → Express のルートハンドラ、View → HTML + JavaScript。

ただし、Node.js のコールバック / async-await や Windows 認証での DB 接続 は初見の人が多いので、ここは丁寧に説明してください。経験者ほど「Linux 向けの mssql 接続記事」を参考にして trustedConnection を外してしまい、接続失敗するパターンがあります。

「知ってるから大丈夫」で環境構築を飛ばすと、後半で SQL Server 接続エラーに苦しむことが多いです。必ず check_sql_env.bat を通してもらってください。

研修中に使うツール・画面の一覧を教えてください

研修で頻繁に使うツールは以下のとおりです。

  • コマンドプロンプト： start.bat 実行、npm install、エラーログ確認
  • ブラウザ（Chrome / Edge 推奨）： http://localhost:3000 で掲示板表示、F12 で開発者ツール
  • SSMS（SQL Server Management Studio）： データベース・テーブル・データの確認、手動 SQL 実行
  • エディタ（VS Code 推奨）： HTML / CSS / JS / server.js の編集

開発者ツールでは主に Console（JavaScript エラー）、Network（API のリクエスト / レスポンス）、Elements（HTML 構造）の3タブを使います。

研修の評価ポイント（メンター向けチェックリスト）は？

以下の観点で研修生の理解度を確認してください。

  • 環境を自分で（または手順書どおりに）構築・起動できるか
  • フロント → API → DB のデータの流れを図で説明できるか
  • fetch('/api/posts') が何をしているか説明できるか
  • SQL の SELECT / INSERT の基本がわかるか
  • ユーザー入力をそのまま HTML や SQL に埋め込む危険性を理解しているか
  • エラーが出たとき、ログ（黒い画面・F12 Console）を見て調査できるか

複数の研修生が同時に研修する場合の注意点は？

各研修生は自分の PC 上で localhost 環境を動かすため、基本的に互いの環境に影響しません。ただし注意点があります。

  • ポート 3000 は1台の PC で1プロセスのみ。同じ PC で2人が動かす場合はポート競合が起きます
  • SQL Server の BbsDB は PC ごとに独立しているため、他人の投稿データは見えません
  • 質問が集中したら、よくある質問をホワイトボードに書き、個別対応の回数を減らす

この Q&A 資料（qa_mentor.html）を研修生にも共有し、検索機能で自己解決を促すのも有効です。

研修が難しすぎる・簡単すぎる場合の調整方法は？

難しすぎる場合：

  • 課題を1機能に絞る（例：「削除ボタンだけ追加」）
  • server_bk.js の該当部分だけを一緒に読み、コメントを追加する課題に変更
  • CSS のカスタマイズ（色・フォント変更）から入り、達成感を先に作る

簡単すぎる場合：

  • レート制限を自分で実装させる
  • 投稿の編集機能（PUT API）を新規追加させる
  • 「なぜ msnodesqlv8 を使うのか」調査レポートを課題にする

研修終了後のフォローアップで伝えるべきことは？

研修で触れた技術は本番開発の入門に過ぎません。以下を伝えてください。

  • 本番では Windows 認証だけでなく、接続文字列・シークレット管理・HTTPS が必須
  • レート制限は今回のメモリ上の Map 実装ではなく、Redis 等を使うのが一般的
  • フロントエンドは React / Vue 等のフレームワークを使うプロジェクトが多い
  • DB は SQL Server 以外（PostgreSQL 等）も多いが、SQL の考え方は共通

研修リポジトリや *_bk ファイルは、今後の個人学習の参考資料として残しておいて問題ありません。

「わからなくなったら qa_mentor.html を検索する」習慣を伝えると、自律学習につながります。

環境構築・起動

必要なソフトウェアは何ですか？

以下をインストールしてください（バージョンは目安です）。

  • Node.js LTS（v18 以上推奨）— node / npm コマンドが使えること
  • SQL Server Express — インスタンス名 SQLEXPRESS でインストール
  • SSMS（SQL Server Management Studio）— GUI で DB を確認
  • ODBC Driver 17 または 18 for SQL Server — msnodesqlv8 接続に必須

プロジェクトフォルダ（bbs）には package.json があり、npm install で Express と mssql が自動取得されます。

start.bat の使い方を教えてください

bbs フォルダ内の start.bat をダブルクリックするか、コマンドプロンプトで実行します。

cd C:\path\to\bbs
start.bat

バッチは次の順序で処理します。

  1. Node.js の存在確認
  2. check_sql_env.bat による SQL Server 環境チェック
  3. 既存の node.exe プロセス終了（ポート解放）
  4. npm install で依存ライブラリ取得
  5. ブラウザで http://localhost:3000 を開き、node server.js を起動
黒い画面（コマンドプロンプト）を閉じるとサーバーが停止します。研修中は開いたままにしてください。終了は Ctrl + C です。

start.bat と start_bk.bat の違いは？

どちらも前処理（Node.js 確認、SQL チェック、npm install）は同じです。違いは起動するサーバーと開く URL です。

  • start.bat → node server.js → http://localhost:3000（研修生用 index.html）
  • start_bk.bat → node server_bk.js → http://localhost:3000/index_bk.html（メンター用完成版）

同時に両方を起動することはできません（どちらもポート 3000 を使用）。切り替える場合は前のコマンドプロンプトを Ctrl + C で止めてから、もう一方を実行してください。

check_sql_env.bat は何をチェックしていますか？

check_sql_env.bat は Node.js 起動前に SQL Server 接続の前提条件を6段階で確認します。

  1. （省略番号あり）SQL Server（SQLEXPRESS）サービスの存在と起動状態
  2. ODBC Driver 17/18 のインストール確認（レジストリ参照）
  3. TCP/IP プロトコルの有効化（scripts\enable_tcp_ip.ps1 を実行、必要なら SQL Server 再起動）
  4. sqlcmd による localhost\SQLEXPRESS への Windows 認証接続テスト

いずれかが失敗すると CHECK_FAILED=1 となり、start.bat は続行しません。表示された ❌ メッセージに従って修正してください。

sqlcmd が無い環境では接続テストがスキップされます。その場合は SSMS で手動接続できるか必ず確認してください。

Node.js が見つからないエラーが出ます

start.bat 実行時に「Node.js が見つかりません」と表示される場合：

  1. https://nodejs.org/ から LTS 版をインストール
  2. インストール時に「Add to PATH」にチェックが入っているか確認
  3. コマンドプロンプトを新しく開き、node -v と npm -v が表示されるか確認

インストール後も認識されない場合は PC を再起動するか、環境変数 PATH に Node.js のパス（例：C:\Program Files\nodejs\）が含まれているか確認してください。

npm install でエラーが出ます

よくある原因と対処：

  • ネットワーク / プロキシ： 社内プロキシ環境では npm config set proxy が必要な場合あり。メンターに確認
  • 権限不足： プロジェクトフォルダが読み取り専用でないか確認。OneDrive 同期フォルダはトラブルの元になりやすい
  • msnodesqlv8 のビルド： 通常はプリビルド版が入りますが、Visual Studio Build Tools が求められる場合はメンターに相談

成功すると node_modules フォルダが作成されます。package.json の依存は express、mssql、msnodesqlv8 の3つです。

ポート 3000 が既に使われている場合は？

start.bat は起動前に taskkill /f /im node.exe で既存の Node プロセスを終了します。それでもポート競合する場合：

  1. 他のコマンドプロンプトで node server.js が動いていないか確認
  2. netstat -ano | findstr :3000 で使用プロセスの PID を確認
  3. タスクマネージャーで該当プロセスを終了

どうしても解放できない場合は、server.js の const PORT = 3000; を 3001 等に変更し、ブラウザの URL も合わせて変更します（研修標準は 3000 のまま推奨）。

localhost\SQLEXPRESS 以外のサーバー名を使っています

SSMS の接続ダイアログに表示されるサーバー名が localhost\SQLEXPRESS と異なる場合（例：.\SQLEXPRESS、DESKTOP-XXX\SQLEXPRESS）、server.js の接続設定を合わせる必要があります。

const config = {
    server: 'localhost\\SQLEXPRESS',  // ← SSMS で接続できた名前に変更
    database: 'master',
    options: {
        trustedConnection: true,
        trustServerCertificate: true
    }
};

バックスラッシュは JavaScript 文字列内で \\ とエスケープしてください。check_sql_env.bat の SQL_SERVER 変数も同様に変更が必要です。

SQL Server Browser サービスが起動しません

名前付きインスタンス SQLEXPRESS へ接続するには SQL Server Browser が必要です。

  1. 管理者としてコマンドプロンプトを開く
  2. net start SQLBrowser を実行
  3. 失敗する場合は services.msc を開き、「SQL Server Browser」を探して開始
  4. スタートアップの種類を「自動」に設定すると次回以降楽になります
Browser サービスがインストールされていない場合、SQL Server Express のインストール時に「共有機能」で Browser を有効にするか、再インストールが必要になることがあります。

ODBC Driver が見つかりませんと表示されます

msnodesqlv8 は ODBC 経由で SQL Server に接続します。以下からドライバーをインストールしてください。

ODBC Driver for SQL Server ダウンロード（Microsoft）

「ODBC Driver 17 for SQL Server」または「ODBC Driver 18 for SQL Server」のいずれかで OK です。インストール後、check_sql_env.bat を再実行してください。

TCP/IP プロトコルの有効化はなぜ必要ですか？

SQL Server Express は既定で TCP/IP が無効な場合があります。Node.js の mssql/msnodesqlv8 ドライバーは TCP 接続を使うため、無効だと ConnectionError が発生します。

check_sql_env.bat は PowerShell スクリプト scripts\enable_tcp_ip.ps1 で状態を確認し、無効なら有効化して SQL Server（MSSQL$SQLEXPRESS）を再起動します。

手動で設定する場合：SQL Server Configuration Manager → SQL Server ネットワークの構成 → SQLEXPRESS のプロトコル → TCP/IP を「有効」→ SQL Server サービス再起動。

ブラウザは開くが「投稿一覧」が空のまま / エラーになる

ブラウザが開いても API が動いていない場合があります。確認手順：

  1. コマンドプロンプトに「サーバーが起動しました: http://localhost:3000」と表示されているか
  2. 「【エラー】データベース初期化に失敗しました」が出ていないか
  3. ブラウザで直接 http://localhost:3000/api/posts を開き、JSON が返るか（空配列 [] でも OK）
  4. F12 → Network タブで /api/posts のステータスコードを確認（200 以外はサーバー側エラー）

npm start や package.json の scripts は使えますか？

package.json には次のスクリプトが定義されています。

"scripts": {
  "start": "node server.js",
  "start:mentor": "node server_bk.js"
}

bbs フォルダで npm start（研修生用）や npm run start:mentor（メンター用）も使えます。ただし研修では SQL 環境チェックやブラウザ自動起動も含む start.bat の利用を推奨します。

Mac / Linux でも動かせますか？

本研修は Windows + SQL Server Express + Windows 認証 を前提に設計されています。trustedConnection: true と msnodesqlv8 は Windows 専用の構成です。

SQL Server・SSMS・DB

BbsDB データベースはいつ・どうやって作られますか？

server.js（および server_bk.js）起動時の initializeDatabase() が自動作成します。流れは次のとおりです。

  1. まず master データベースに接続
  2. SELECT name FROM sys.databases WHERE name = 'BbsDB' で存在確認
  3. 無ければ CREATE DATABASE BbsDB を実行
  4. BbsDB に再接続し、Posts テーブルを確認・作成

手動で作りたい場合は db/init.sql を SSMS で実行しても構いません（既存 DB を DROP して作り直す内容なので注意）。

Posts テーブルの構造を教えてください

研修生用（server.js）の初期構造：

CREATE TABLE Posts (
    Id INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(50) NOT NULL,
    Message NVARCHAR(MAX) NOT NULL,
    CreatedAt DATETIME DEFAULT GETDATE()
)

メンター用（server_bk.js）では Reactions カラムが追加されます。

Reactions NVARCHAR(500) NOT NULL DEFAULT '{}'

既存テーブルに後から追加する場合、サーバー起動時に ALTER TABLE Posts ADD Reactions ... が自動実行されます。

SSMS で BbsDB に接続する手順は？

  1. SSMS を起動
  2. サーバー名に localhost\SQLEXPRESS（または環境に合った名前）を入力
  3. 認証は「Windows 認証」を選択 → 接続
  4. オブジェクトエクスプローラーで「データベース」→ BbsDB を展開
  5. テーブル → dbo.Posts を右クリック → 「上位 1000 行を選択」でデータ確認
サーバー起動前は BbsDB が存在しないことがあります。一度 start.bat を実行してから SSMS を更新（F5）してください。

Windows 認証（trustedConnection）とは何ですか？

Windows 認証は、SQL Server が現在ログインしている Windows ユーザーの身元を使って接続する方式です。server.js では次の設定で有効化しています。

options: {
    trustedConnection: true,
    trustServerCertificate: true
}

ユーザー名 / パスワードをコードに書く必要がなく、研修環境では設定が簡単です。ただし接続できるのは SQL Server 側で権限を持つ Windows アカウントのみです。通常、自分の PC の管理者 / ユーザーアカウントであれば問題ありません。

IDENTITY(1,1) と PRIMARY KEY の意味は？

Id INT IDENTITY(1,1) PRIMARY KEY の意味：

  • INT： 整数型の識別子
  • IDENTITY(1,1)： INSERT 時に 1 から始まり、1 ずつ自動採番（1, 2, 3, ...）
  • PRIMARY KEY： 各行を一意に識別する主キー。重複不可

投稿削除 API（DELETE /api/posts/:id）ではこの Id を指定して対象行を削除します。

NVARCHAR と VARCHAR の違いは？日本語投稿に関係ありますか？

NVARCHAR は Unicode 文字列を格納し、日本語・絵文字を正しく保存できます。VARCHAR は非 Unicode で、日本語環境では文字化けの原因になりやすいです。

本プロジェクトでは Name NVARCHAR(50)、Message NVARCHAR(MAX) としているため、日本語の名前・本文・リアクション絵文字を問題なく保存できます。Node.js 側でも sql.NVarChar 型でパラメータを渡しています。

GETDATE() と CreatedAt カラムはどう使われますか？

CreatedAt DATETIME DEFAULT GETDATE() により、INSERT 時に CreatedAt を省略すると SQL Server が現在日時を自動設定します。

API の取得クエリは ORDER BY CreatedAt DESC（新しい順）が基本です。server_bk.js では ?sort=asc で古い順にも切り替えられます。フロントの formatRelativeTime() が「3分前」等の表示に使います。

手動で SQL を実行してテストデータを入れたい

SSMS で BbsDB を選択し、「新しいクエリ」から以下を実行できます。

USE BbsDB;
INSERT INTO Posts (Name, Message) VALUES (N'テスト太郎', N'これはテスト投稿です');
SELECT * FROM Posts ORDER BY CreatedAt DESC;

文字列リテラルには N'...' プレフィックスを付けて Unicode として扱います。ブラウザを更新すると API 経由でも同じデータが表示されます。

投稿データをすべて削除してリセットしたい

データのみ消す場合：

USE BbsDB;
DELETE FROM Posts;
-- または IDENTITY をリセットしたい場合
TRUNCATE TABLE Posts;

DB ごと作り直す場合は db/init.sql を実行するか、SSMS でデータベースを削除してサーバーを再起動（自動再作成）します。

DROP DATABASE 実行中にサーバーが接続中だと失敗します。先に Ctrl + C で Node サーバーを停止してください。

Reactions カラムに保存されている JSON の形式は？

メンター版ではリアクション数が JSON 文字列として保存されます。例：

{"👍":3,"🎉":1,"❤️":2}

サーバーは parseReactions() で JSON をオブジェクトに変換して API レスポンスに含め、フロントでボタン表示に使います。許可絵文字は ALLOWED_EMOJIS でホワイトリスト管理されています。

パラメータ化クエリ（.input()）は SSMS でも使えますか？

概念は同じです。SSMS では次のように変数を使います。

DECLARE @name NVARCHAR(50) = N'山田';
DECLARE @message NVARCHAR(MAX) = N'こんにちは';
INSERT INTO Posts (Name, Message) VALUES (@name, @message);

Node.js では pool.request().input('name', sql.NVarChar(50), name) がこれに相当します。研修のセキュリティパートでは「文字列連結で SQL を組み立てない」理由を、この対比で説明すると理解が深まります。

LIKE 検索（%キーワード%）の仕組みを教えてください

server_bk.js の検索は次のクエリです。

SELECT * FROM Posts
WHERE Name LIKE @search OR Message LIKE @search
ORDER BY CreatedAt DESC

@search には %研修% のように前後に %（任意の文字列）を付けたパターンが渡されます。SQL インジェクションを防ぐため、キーワードは必ず .input('search', sql.NVarChar(100), searchPattern) で渡し、文字列連結はしません。

sys.tables や sys.databases を使った確認クエリの意味は？

サーバー起動時の存在確認に使っています。

SELECT name FROM sys.databases WHERE name = 'BbsDB'
SELECT * FROM sys.tables WHERE name = 'Posts'
SELECT COL_LENGTH('Posts', 'Reactions') AS ColLen

sys.* は SQL Server のシステムカタログ（メタデータ）です。SSMS のオブジェクトエクスプローラーで見える情報と同じものを SQL で取得しています。マイグレーション（カラム追加）の自動化パターンとして参考になります。

接続プール（pool）とは何ですか？

let pool; に sql.connect(config) の結果を保持し、各 API リクエストで pool.request() を使い回します。毎回接続し直すより効率的です。

初期化はサーバー起動時に1回だけ。initializeDatabase() が成功した後に startServer() で HTTP リッスンを開始するため、DB 接続できない状態では API は公開されません。

mssql と msnodesqlv8 の違いは？なぜ msnodesqlv8 を使うのですか？

mssql パッケージは複数のドライバーをサポートします。通常の TCP + SQL 認証では標準ドライバーで足りますが、Windows 認証（trustedConnection） には mssql/msnodesqlv8 が必要です。

const sql = require('mssql/msnodesqlv8');

内部では ODBC Driver 17/18 を介して SQL Server に接続します。だから check_sql_env.bat で ODBC の確認が入っています。

SSMS で「データベースに接続できません」と出ます

Node.js 以前に SSMS で接続できることが前提です。確認項目：

  • SQL Server（SQLEXPRESS）サービスが起動しているか（services.msc）
  • サーバー名の typo（localhost\SQLEXPRESS）
  • リモート接続ではないか（研修はローカルのみ）
  • ファイアウォールがブロックしていないか（ローカルホストは通常問題なし）

SSMS で接続できれば、check_sql_env.bat の [6/6] も通るはずです。

トランザクションや複数テーブル設計は研修に含まれますか？

標準研修では Posts 単一テーブルの CRUD のみです。トランザクション（BEGIN TRAN）、外部キー、正規化は発展課題として紹介する程度で OK です。

発展例：コメントテーブル Comments を追加し PostId で紐づける、ユーザー認証テーブルを作る、など。

DB のバックアップを取る方法は？（任意）

研修発表前にデータを残したい場合、SSMS で BbsDB を右クリック → 「タスク」→「バックアップ」で .bak ファイルを作成できます。

簡易的には SELECT * FROM Posts の結果を CSV エクスポートするだけでも十分なことが多いです。

Node.js・Express・server.js

server.js の全体の流れを説明してください

  1. Express アプリ作成、ポート 3000 設定
  2. express.json() で JSON ボディをパース、express.static('public') で静的ファイル配信
  3. SQL Server 接続設定（localhost\SQLEXPRESS、Windows 認証）
  4. initializeDatabase() で BbsDB / Posts を自動作成
  5. 成功後 startServer() で GET/POST /api/posts を定義し app.listen(3000)

最後の行 initializeDatabase(); がすべての起点です。

express.json() と express.static() は何をしていますか？

express.json() は POST リクエストの JSON ボディ（{ "name": "...", "message": "..." }）を req.body に変換するミドルウェアです。

express.static(path.join(__dirname, 'public')) は public フォルダ内の HTML / CSS / JS を URL で直接配信します。だから http://localhost:3000/index.html で画面が開けます。

GET /api/posts の処理内容は？

研修生版の実装：

app.get('/api/posts', async (req, res) => {
    let result = await pool.request()
        .query('SELECT * FROM Posts ORDER BY CreatedAt DESC');
    res.json(result.recordset);
});

recordset は行の配列です。フロントの fetch('/api/posts') がこれを受け取り、画面に描画します。メンター版では検索（?search=）と並び替え（?sort=asc）が追加されています。

POST /api/posts の処理内容は？

新規投稿 API。流れ：

  1. req.body から name、message を取得
  2. 空なら 400 エラー
  3. パラメータ化 INSERT を実行
  4. 成功時 201、失敗時 500
await pool.request()
    .input('name', sql.NVarChar(50), name)
    .input('message', sql.NVarChar(sql.MAX), message)
    .query('INSERT INTO Posts (Name, Message) VALUES (@name, @message)');

async / await を使う理由は？

DB クエリは時間がかかる非同期処理です。await pool.request().query(...) はクエリ完了まで待ち、結果を受け取ってから res.json() します。

async 関数内で try/catch を使うと SQL エラーを捕捉して 500 レスポンスを返せます。研修生には「コールバック地獄より読みやすい」と説明するとよいでしょう。

server_bk.js にある DELETE API の仕組みは？

app.delete('/api/posts/:id', async (req, res) => {
    const postId = Number(req.params.id);
    if (!Number.isInteger(postId) || postId <= 0) {
        return res.status(400).json({ error: '不正な投稿IDです。' });
    }
    const result = await pool.request()
        .input('id', sql.Int, postId)
        .query('DELETE FROM Posts WHERE Id = @id');
    // rowsAffected で存在確認
});

:id は URL パラメータです。Number() で数値化し、文字列 "abc" や "1; DROP TABLE" を弾きます。

リアクション API（POST /api/posts/:id/react）はどう動きますか？

  1. リクエストボディの emoji が ALLOWED_EMOJIS に含まれるか検証
  2. 該当投稿の Reactions JSON を SELECT
  3. パースして該当絵文字のカウントを +1
  4. UPDATE Posts SET Reactions = @reactions で保存
  5. 更新後のオブジェクトを JSON で返却

任意の文字列を DB に書き込ませないホワイトリスト設計がポイントです。

HTTP ステータスコード 200 / 201 / 400 / 404 / 429 / 500 の使い分けは？

  • 200： 取得成功、削除成功
  • 201： 新規作成（POST 投稿）成功
  • 400： クライアントの入力ミス（必須項目不足、不正 ID）
  • 404： 指定 ID の投稿が存在しない
  • 429： レート制限超過（1分に10回以上投稿）
  • 500： サーバー内部エラー（SQL 例外など）

メンター版は res.status(400).json({ error: '...' }) のように JSON でエラー詳細を返し、フロントのトースト表示と連携します。

initializeDatabase() が失敗すると process.exit(1) する理由は？

DB なしでは掲示板の核心機能が動きません。初期化失敗のまま HTTP サーバーだけ起動すると、ユーザーには「動いているように見えて投稿だけ失敗する」混乱が起きます。

早期にプロセスを終了し、コマンドプロンプトにエラーを表示することで、研修生が環境問題に気づけるようにしています。

req.body と req.query と req.params の違いは？

  • req.body： POST の JSON ボディ（name, message, emoji）
  • req.query： URL のクエリ文字列（/api/posts?search=研修&sort=asc）
  • req.params： ルートパラメータ（/api/posts/5 の id=5）

フロントの fetch でどこにデータを載せるかと対になっているので、セットで教えてください。

CORS エラーは出ますか？

本構成ではフロント（index.html）も API（/api/posts）も同じオリジン（http://localhost:3000）から配信されるため、通常 CORS エラーは発生しません。

別ポートや別ドメインから API を呼ぶと CORS 設定が必要になりますが、研修範囲外です。

ログ（console.log / console.error）の見方は？

サーバーログは start.bat の黒い画面に出力されます。主なメッセージ：

  • SQL Server (master) に接続しています... — 初期化開始
  • データベース 'BbsDB' に接続しました。 — 成功
  • 【エラー】データベース初期化に失敗しました: — 接続失敗（詳細が続く）
  • [セキュリティ警告] 疑わしい入力を検知 — server_bk.js のみ、攻撃パターン検知

研修生にはエラー時「まず黒い画面を読む」習慣を付けさせてください。

新しい API エンドポイントを追加する手順は？

  1. startServer() 内（または initializeDatabase().then() 内）に app.get/post/put/delete(...) を追加
  2. 入力バリデーション → パラメータ化クエリ → レスポンス返却の順で実装
  3. サーバー再起動
  4. ブラウザまたは curl / Postman でテスト
  5. フロントの fetch を追加

例：投稿編集 PUT /api/posts/:id は DELETE を参考にすると実装しやすいです。

JSON レスポンスと res.send() の違いは？

研修生版は res.status(201).send('投稿が完了しました。') のようにプレーンテキストを返す箇所があります。メンター版は res.status(201).json({ message: '投稿が完了しました。' }) が基本です。

フロントが response.json() でパースするなら、サーバーも JSON で統一した方がエラーメッセージ（{ error: '...' }）の扱いが楽です。

express.json({ limit: '16kb' }) はなぜ必要ですか？

リクエストボディの最大サイズを制限し、巨大 JSON によるメモリ消費（DoS の一種）を防ぎます。掲示板の投稿データは小さいため 16kb で十分です。メンター版 server_bk.js のみ設定されています。

セキュリティヘッダーを付与するミドルウェアの意味は？

server_bk.js では全レスポンスに以下を設定しています。

  • X-Content-Type-Options: nosniff — MIME タイプの誤解釈防止
  • X-Frame-Options: DENY — iframe 埋め込み防止（クリックジャッキング対策）
  • X-XSS-Protection: 1; mode=block — ブラウザの XSS フィルタ有効化
  • Referrer-Policy — リファラー情報の制御
  • X-Powered-By 削除 — Express 使用の露出を抑える

sort パラメータを SQL に渡すときの注意点は？

server_bk.js では const sort = req.query.sort === 'asc' ? 'ASC' : 'DESC'; とし、ホワイトリストで ASC/DESC のみ許可しています。

ORDER BY ${req.query.sort} のようにユーザー入力をそのまま SQL に埋め込むと SQL インジェクションの脆弱性になります。並び順のような「選択肢が決まっている値」は必ずサーバー側で検証してください。

server.js を server_bk.js に段階的に近づけるロードマップは？

  1. JSON エラーレスポンスの統一
  2. 入力バリデーション（文字数上限、trim、sanitizeInput）
  3. 検索 API（LIKE + パラメータ化）
  4. DELETE / リアクション API
  5. レート制限
  6. セキュリティヘッダー、疑わしい入力ログ

1機能ずつ追加・テストする方が、一気にコピーするより学習効果が高いです。

HTML・CSS・フロント

index.html と index_bk.html の構造の違いは？

研修生版 index.html はシンプルな構成（タイトル、投稿フォーム、投稿一覧）のみです。メンター版 index_bk.html には以下が追加されています。

  • メンター用バナー、セキュリティ解説パネル（<details>）
  • 文字数カウンター、名前記憶チェックボックス
  • 検索ボックス、並び替え、自動更新トグル、更新ボタン
  • ダークモードボタン、トーストコンテナ、紙吹雪用 canvas

研修ではまず研修生版の HTML を読み、1要素ずつ index_bk.html から移植する課題が効果的です。

セマンティック HTML（article, section, time）を使う理由は？

index_bk.html では <section>、<article class="post-card">、<time datetime="..."> などを使い、構造を明確にしています。メリット：

  • スクリーンリーダーなど支援技術が読みやすい（アクセシビリティ）
  • CSS でのスタイリングの単位が明確
  • JavaScript で .post-card を探して DOM 操作しやすい

ダークモードの実装原理を教えてください

script_bk.js では document.documentElement.setAttribute('data-theme', 'dark') で <html> 要素に属性を付け、style_bk.css 側で [data-theme="dark"] セレクタにより色変数を切り替えます。

設定は localStorage の bbs_dark_mode キーに保存され、次回訪問時に loadSavedSettings() で復元されます。ボタンのアイコンは 🌙 / ☀️ で切り替わります。

CSS のクラス設計（BEM 風）について

style_bk.css では post-card、post-card__body、post-name、btn--loading のように、ブロック・要素・修飾子を意識した命名がされています。研修生が CSS を追加する際も、既存の命名規則に合わせると保守しやすくなります。

トースト通知（showToast）とは何ですか？

画面端に一時的に表示されるフィードバック UI です。投稿成功・失敗・コピー完了などに使います。

showToast('投稿が完了しました', 'success');
showToast(data.error || '投稿に失敗しました', 'error');

toast--success、toast--error、toast--info で色分け。3秒後に自動で消えます。研修生版にはないため、UX 改善の移植課題として人気があります。

文字数カウンター（0 / 50）の実装ポイントは？

input / textarea の input イベントで updateCharCount() を呼び、90% 以上で警告色、100% で危険色のクラスを付けます。HTML 側の maxlength 属性とサーバー側の LIMITS の二重チェックで不正入力を防ぎます。

ローディング状態・空状態・エラー状態の UI は？

script_bk.js の loadPosts() は3状態を切り替えます。

  • loading-state： スピナー +「投稿を読み込み中...」
  • empty-state： 投稿0件または検索結果0件
  • error-state： API 失敗時、再試行を促すメッセージ

研修生版はエラー時 Console のみなので、ユーザー向けメッセージの追加は優先度の高い改善です。

アバター（イニシャル + 色）の仕組みは？

getInitials(name) で名前の先頭1文字、getAvatarColor(name) で名前のハッシュから HSL 色相を生成し、同じ名前なら常に同じ色になります。CSS の style="background: hsl(...)" でインライン適用しています。

表示名は escapeHTML() 済み。色はサーバー値ではなくクライアント生成なので XSS リスクは低いです。

相対時間表示（3分前）はどう実装されていますか？

formatRelativeTime(dateString) が CreatedAt と現在時刻の差分を計算し、60秒未満なら「たった今」、60分未満なら「N分前」と表示します。<time> 要素の title 属性には絶対日時（toLocaleString('ja-JP')）を入れ、ホバーで詳細が見えます。

紙吹雪（confetti）エフェクトはいつ発動しますか？

投稿成功時の launchConfetti() と、コナミコマンド成功時に canvas 上でパーティクルアニメーションを約90フレーム再生します。confettiCanvas は全画面固定の canvas 要素です。装飾機能ですが、Canvas API の学習題材にもなります。

レスポンシブ対応（スマホ表示）の状態は？

index_bk.html には viewport メタタグがあり、style_bk.css にメディアクエリでモバイル向け調整が入っています。研修の主戦場は PC ですが、スマホで確認してレイアウト崩れを直すのは良い CSS 課題です。

aria 属性（aria-live, aria-busy, aria-label）の使い方は？

アクセシビリティ向上のため、動的に変わる要素に ARIA を付与しています。

  • postCount に aria-live="polite" — 件数更新を読み上げ
  • 読み込み中の postsContainer に aria-busy="true"
  • 削除ボタンに aria-label="〇〇さんの投稿を削除"

フォームの novalidate 属性はなぜ付いていますか？

ブラウザ標準のバリデーション UI を無効化し、JavaScript とサーバー側のバリデーションに統一するためです。標準 UI はブラウザごとに見た目が異なり、カスタムトーストと併用すると二重メッセージになることがあります。

party-mode（コナミコマンド）の CSS は？

コナミコマンド成功時に document.body.classList.add('party-mode') が5秒間付与され、style_bk.css で背景アニメーションや装飾が有効になります。隠し機能として研修の息抜き・モチベーション用途です。

CSS を変更したのに反映されない

  1. ブラウザのスーパーリロード（Ctrl + Shift + R）
  2. index.html が参照する CSS ファイル名が正しいか（style.css vs style_bk.css）
  3. 開発者ツール → Network で CSS が 304/200 で読み込まれているか
  4. セレクタの詳細度や typo で上書きされていないか

JavaScript・API通信

DOMContentLoaded でラップする理由は？

document.addEventListener('DOMContentLoaded', () => { ... }) は HTML の DOM 構築完了後に JavaScript を実行します。これより前に getElementById すると要素が null になります。<script src="script.js"> を </body> 直前に置くのも同様の目的です。

fetch('/api/posts') の基本パターンを教えてください

async function loadPosts() {
    const response = await fetch('/api/posts');
    if (!response.ok) throw new Error('取得失敗');
    const posts = await response.json();
    // posts は配列。各要素に Id, Name, Message, CreatedAt
}

相対 URL /api/posts は同じホスト（localhost:3000）に向かいます。絶対 URL を使う必要はありません。

POST 投稿の fetch の書き方は？

const response = await fetch('/api/posts', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name: nameInput.value, message: messageInput.value })
});

Content-Type: application/json を付けないとサーバーの express.json() がボディを正しく解釈できません。成功後はフォームクリアと loadPosts() で一覧を更新します。

innerHTML で投稿を表示する際の XSS 対策は？

ユーザー入力（名前・本文）は必ず escapeHTML() してから innerHTML に埋め込みます。

function escapeHTML(str) {
    return String(str).replace(/[<>'"]/g,
        tag => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;',
                 "'": '&#39;', '"': '&quot;' }[tag] || tag));
}
<script>alert(1)</script> を本文に入れてエスケープなし表示するとスクリプトが実行されます。研修ではわざと試して危険性を体感させると効果的です（メンター監督下で）。

検索機能のデバウンス（300ms）とは？

検索ボックスの input イベントごとに API を呼ぶとキー入力のたびにリクエストが飛びます。setTimeout で300ms 待ち、入力が止まってから loadPosts() するのがデバウンスです。

searchInput.addEventListener('input', () => {
    clearTimeout(searchDebounceTimer);
    searchDebounceTimer = setTimeout(loadPosts, 300);
});

URLSearchParams でクエリを組み立てる方法は？

const params = new URLSearchParams();
if (search) params.set('search', search);
if (sort) params.set('sort', sort);
const url = `/api/posts${params.toString() ? '?' + params.toString() : ''}`;

日本語キーワードも自動で URL エンコードされます。手動で ?search= + 文字列連結より安全で読みやすいです。

DELETE とリアクション API の fetch 例は？

// 削除
await fetch(`/api/posts/${postId}`, { method: 'DELETE' });

// リアクション
await fetch(`/api/posts/${postId}/react`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ emoji: '👍' })
});

レスポンスは response.json() でパースし、data.error をトースト表示します。

イベント委譲ではなく個別 addEventListener を使っている理由は？

loadPosts() のたびに HTML を再生成するため、削除・リアクション・コピーボタンに都度 addEventListener を付け直しています。代替案として postsContainer に1つリスナーを付けるイベント委譲パターンも教えると発展的な学びになります。

localStorage の使い方（名前記憶・ダークモード）

localStorage.setItem('bbs_username', name);
localStorage.getItem('bbs_username');
localStorage.removeItem('bbs_username');

ブラウザに永続保存され、同じ PC・同じブラウザで次回も残ります。機密情報（パスワード）は絶対に保存しないよう指導してください。研修では表示名のみです。

Ctrl + Enter で投稿する実装は？

messageInput.addEventListener('keydown', (e) => {
    if (e.ctrlKey && e.key === 'Enter') {
        e.preventDefault();
        postForm.requestSubmit();
    }
});

長文入力時の UX 改善です。requestSubmit() は HTML5 のフォーム送信 API で、submit イベントリスナーが発火します。

自動更新（30秒 interval）の注意点は？

setInterval(loadPosts, 30000) で定期取得します。投稿フォーム入力中に一覧が更新されると UX が悪い場合があるため、チェックボックスで ON/OFF 切替にしています。ページを離れるときは clearInterval でタイマー解除が望ましいです（現行コードはページ内のみ想定）。

const konamiCode = ['ArrowUp','ArrowUp','ArrowDown','ArrowDown',

let konamiIndex = 0;

clipboard API で本文コピーする方法は？

二重送信・二重取得を防ぐガードです。投稿ボタン連打で同じ内容が10件投稿されるのを防ぎ、読み込み中に再度 loadPosts() が走るレースコンディションも抑えます。非同期 UI では必須のパターンです。

セキュリティ

SQLインジェクションとは？このプロジェクトではどう防いでいますか？

攻撃者が入力欄に ' OR '1'='1 などを入れ、意図しない SQL を実行させる攻撃です。

対策：パラメータ化クエリ。ユーザー入力は SQL 文字列に連結せず、.input('name', sql.NVarChar(50), name) でパラメータとして渡します。

// 危険（やってはいけない）
.query(`INSERT INTO Posts VALUES ('${name}', '${message}')`)

// 安全（本プロジェクト）
.query('INSERT INTO Posts (Name, Message) VALUES (@name, @message)')

XSS（クロスサイトスクリプティング）とは？

悪意あるスクリプトを投稿本文に含め、他ユーザーが閲覧したときに実行させる攻撃です。対策は escapeHTML() による表示前エスケープです。

サーバー側でも入力サニタイズ（sanitizeInput）がありますが、出力時エスケープが最後の砦です。両方実施する多層防御が理想です。

レート制限（1分10回）の仕組みを教えてください

server_bk.js の rateLimitStore（Map）に IP ごとの投稿回数を記録します。

const RATE_LIMIT = { windowMs: 60 * 1000, maxPosts: 10 };
function checkRateLimit(clientIp) {
    // 1分経過でカウントリセット
    // 10回超えたら false → 429 レスポンス
}

研修用の簡易実装で、サーバー再起動でリセットされます。本番では Redis 等を使います。

logSuspiciousInput は何をしていますか？

SUSPICIOUS_PATTERNS 正規表現配列で SQL インジェクションっぽい文字列を検知し、コンソールに警告ログを出します。実際の防御はパラメータ化クエリが担い、ログは学習・監視用です。

/'\s*or\s+'/i
/\bunion\b.+\bselect\b/i
/\b(drop|alter|exec|execute)\b/i

sanitizeInput（制御文字除去）の必要性は？

NULL バイト（\0）や制御文字が入力に混ざると、古いシステムでは文字列処理のバグやログ改ざんの原因になります。sanitizeInput() で除去してからバリデーションします。

絵文字ホワイトリスト（ALLOWED_EMOJIS）の理由は？

リアクション API で任意の文字列を Reactions JSON に保存させないためです。巨大文字列や不正 JSON で DB を汚染する攻撃を防ぎます。許可リスト外の絵文字は 400 エラーです。

投稿 ID の Number() 検証はなぜ重要ですか？

DELETE /api/posts/abc や /api/posts/1;DROP TABLE Posts-- のような URL を弾くためです。Number() + Number.isInteger() + postId > 0 の三重チェック後、sql.Int 型でパラメータ化します。

研修で SQL インジェクションを安全に体験する方法は？

メンター監督下で、わざと脆弱なクエリ（ローカル検証用の一時コード）に ' OR '1'='1 を入れてみせ、パラメータ化版と結果の違いを比較します。研修生の PC で本番 DB に脆弱コードを残さないよう、必ず元に戻すか、別の検証用エンドポイントに限定してください。

CSRF 対策は必要ですか？

本掲示板は認証なし・同一オリジン利用の研修ツールのため CSRF トークンは実装していません。ログイン機能や Cookie 認証を追加する課題では CSRF 対策の必要性を説明してください。

trustServerCertificate: true は安全ですか？

開発環境では自己署名証明書の検証をスキップするために使います。本番では正式な TLS 証明書と適切な検証設定を使うべきです。研修ではローカル接続の簡便さのため許容しています。

パスワードや API キーをコードに書かない理由は？

Windows 認証を使うから DB パスワードは不要ですが、将来 SQL 認証に変える場合は環境変数（process.env.DB_PASSWORD）や .env ファイル（gitignore 必須）で管理します。Git にシークレットをコミットしないよう指導してください。

Content-Security-Policy（CSP）は実装されていますか？

現行の server_bk.js では CSP ヘッダーは未設定です。XSS 対策は出力エスケープが中心。発展課題として Content-Security-Policy: default-src 'self' の追加を提案できます。

削除機能に認証がないのは問題では？

本番では誰でも削除できるのは重大な問題です。研修では API の CRUD 学習を優先し、認証は省略しています。発展課題として「自分の投稿だけ削除」「管理者のみ削除」などの認可設計を議論させてください。

express.json の 16kb 制限を超えるとどうなりますか？

リクエストが拒否され、通常 413 Payload Too Large 相当のエラーになります。掲示板の用途（500文字本文）では問題になりません。意図的に巨大 JSON を送る DoS 試験はメンター監督下でのみ行ってください。

セキュリティパネル（index_bk.html）の使い方（メンター向け）

完成版画面の「セキュリティ対策について」折りたたみパネルに、実装済み対策の一覧があります。Day 4〜5 で研修生に開かせ、自分の server.js に足りない項目をチェックリスト化させると、自走学習に繋がります。

エラー・トラブルシューティング

ConnectionError [object Object] が表示されます

Node.js から SQL Server への接続に失敗したときの典型的なエラーです。[object Object] とだけ見えるのは、Error オブジェクトを文字列連結したためで、直前の行に詳細が出ていることが多いです。

対処手順：

  1. check_sql_env.bat を単独実行し、❌ 項目を修正
  2. SSMS で localhost\SQLEXPRESS に接続できるか確認
  3. server.js の server 名が SSMS と一致しているか確認
  4. SQL Server（SQLEXPRESS）サービスが起動しているか確認
  5. ODBC Driver 17/18 がインストールされているか確認
メンターは研修生の黒い画面のエラーをスクリーンショットまたは全文コピーで受け取ると原因特定が早いです。

【エラー】データベース初期化に失敗しました と出てサーバーが止まります

initializeDatabase() の catch で process.exit(1) しています。HTTP サーバーは起動しません。原因はほぼ常に SQL 接続問題です。q-err-01 と同じ手順で環境を修正してください。

投稿の取得に失敗しました（フロントの error-state）

ブラウザは開けているが API が失敗している状態です。

  1. コマンドプロンプトでサーバーが動いているか
  2. http://localhost:3000/api/posts を直接開いて JSON が返るか
  3. F12 Network でステータスコード（500, 404, (failed)）を確認
  4. (failed) の場合はサーバー未起動または URL typo

投稿しても 400 エラー（名前と本文は必須です）

サーバーが req.body.name / message を空と判断しています。原因：

  • フォームが空のまま送信
  • Content-Type: application/json ヘッダー不足
  • express.json() ミドルウェアが無効
  • プロパティ名の typo（username vs name）

Network タブの Request Payload を確認してください。

429 投稿が多すぎます エラーが出ます

server_bk.js のレート制限（1分10回）に達しました。1分待つか、テスト中は一時的に maxPosts を上げてください。サーバー再起動でカウントはリセットされます。

Cannot find module 'express' / 'mssql'

node_modules が無いか壊れています。bbs フォルダで npm install を実行してください。start.bat は自動で実行しますが、手動で node server.js した場合は自分で install が必要です。

EADDRINUSE: address already in use :::3000

ポート 3000 が既に使用中です。別の node server.js が動いていないか確認し、taskkill /f /im node.exe で終了するか、start.bat を使ってください（自動クリーンアップあり）。

画面は真っ白 / スタイルが当たっていない

  • CSS ファイルパス（href="style.css"）が正しいか
  • public フォルダにファイルがあるか
  • URL が file:///C:/... になっていないか（必ず http://localhost:3000 経由で開く）
HTML を直接ダブルクリックで開くと fetch が CORS / パスエラーになります。必ずサーバー経由でアクセスしてください。

Uncaught TypeError: Cannot read properties of null

getElementById が null を返しています。HTML に該当 id が無い、または JS が DOM 構築前に実行されています。index_bk.html 用の JS を index.html で使っていないか、id の不一致（username vs userName）を確認してください。

SyntaxError: Unexpected token < in JSON at position 0

response.json() したが、返ってきたのは JSON ではなく HTML（エラーページ）です。API URL が間違っている、サーバーが 404 HTML を返している、サーバークラッシュ後にプロキシページが返る、などが原因です。Network の Response 本文を確認してください。

削除ボタンを押しても 404 になる

該当 ID の投稿が既に削除済み、または server.js（削除 API なし）で script_bk.js（削除呼び出しあり）を動かしている不一致が考えられます。サーバーとフロントのペア（研修生用 / メンター用）を揃えてください。

リアクションが効かない / Reactions カラムエラー

server_bk.js は Reactions カラムを必要とします。古い Posts テーブルでサーバーを再起動すれば ALTER TABLE で追加されます。それでも失敗する場合は SSMS でカラムの有無を確認し、手動で追加してください。

日本語が文字化けします

  • HTML の <meta charset="UTF-8"> を確認
  • ファイル保存エンコーディングが UTF-8（BOM なし推奨）か確認
  • DB カラムが NVARCHAR か確認
  • コマンドプロンプトは chcp 65001（start.bat が実行）

npm install で msnodesqlv8 のエラー

ネイティブモジュールのため環境によってはビルドエラーが出ます。Node.js のバージョンを LTS に合わせ、Visual Studio Build Tools が必要な場合があります。社内標準 PC では start.bat 同梱の package-lock.json で通常は成功します。再試行：rmdir /s /q node_modules 後 npm install。

SQL Server の再起動に失敗しました（check_sql_env.bat）

TCP/IP 有効化後の自動再起動に管理者権限が必要な場合があります。管理者 CMD で net stop "MSSQL$SQLEXPRESS" → net start "MSSQL$SQLEXPRESS" を実行するか、services.msc から手動再起動してください。

投稿は成功するが SSMS にデータが見えない

別の SQL Server インスタンスに繋がっている可能性があります。SSMS のサーバー名と server.js の server 設定を照合し、SELECT DB_NAME() で現在の DB を確認してください。また SSMS でクエリ実行後に再読み込み（F5）が必要です。

fetch failed / Failed to fetch（ブラウザ）

ネットワークレベルでサーバーに到達できていません。サーバー停止、ファイアウォール、URL のホスト名 typo（locahost）が原因です。まずコマンドプロンプトに「サーバーが起動しました」があるか確認します。

コードを直したのに挙動が変わらない

  1. server.js 変更後はサーバー再起動必須
  2. 編集したファイルを保存したか（VS Code の白丸が消えたか）
  3. 別フォルダの同名ファイルを編集していないか
  4. ブラウザキャッシュ（スーパーリロード）

PowerShell の実行ポリシーで enable_tcp_ip.ps1 が失敗

check_sql_env.bat は -ExecutionPolicy Bypass 付きで呼びますが、それでも失敗する場合は管理者 PowerShell で手動実行するか、SQL Server Configuration Manager で TCP/IP を手動有効化してください。

トラブルシューティングの優先順位（メンター用フローチャート）

  1. サーバー（黒い画面）は動いているか？ → 動いていなければ start.bat
  2. SQL 初期化エラーか？ → check_sql_env.bat / SSMS 接続
  3. 静的ページは表示されるか？ → /api/posts を直接確認
  4. API は OK だが UI だけおかしいか？ → F12 Console / 要素 id / CSS
  5. 投稿だけ失敗か？ → Network の POST リクエスト / レスポンス本文

この順で切り分けると、8割の問題は「サーバー未起動」「SQL 未接続」「file:// で開いている」のいずれかです。

カスタマイズ・機能追加

掲示板のタイトルやデザインを変えたい

index.html の <h1> と style.css の色・フォントを変更します。メンター版の CSS 変数（:root のカラー定義）を参考にすると、ダークモードとの整合も取りやすいです。

検索機能を追加する手順は？

サーバー： GET /api/posts?search= で LIKE @search クエリ（server_bk.js 参照）。フロント： 検索 input とデバウンス付き loadPosts()。HTML： index_bk.html の searchInput を移植。

投稿削除機能を追加したい

バックエンドに DELETE /api/posts/:id を追加し、フロントに削除ボタンと confirm() ダイアログを実装します。server_bk.js と script_bk.js の deletePost() がそのまま参考になります。

リアクション（絵文字）機能を追加したい

  1. DB に Reactions NVARCHAR(500) DEFAULT '{}' を追加
  2. POST /api/posts/:id/react API を実装
  3. フロントにリアクションボタンと reactToPost() を追加

絵文字はサーバー・クライアント両方でホワイトリスト管理してください。

投稿編集（UPDATE）機能を新規実装する課題

発展課題：PUT /api/posts/:id で Name / Message を更新。フロントは各カードに「編集」ボタンを付け、インライン編集またはモーダルで textarea を表示。パラメータ化 UPDATE Posts SET Message = @message WHERE Id = @id を使います。

ページネーション（件数制限）を追加するには？

?page=1&limit=20 クエリを受け取り、SQL で ORDER BY CreatedAt DESC OFFSET @offset ROWS FETCH NEXT @limit ROWS ONLY（SQL Server 2012+）を使います。フロントに「もっと見る」ボタンを追加するパターンがシンプルです。

おみくじ機能を追加したい

script_bk.js の FORTUNES 配列と、投稿成功後の getRandomFortune() トーストが参考になります。サーバー変更は不要な純フロント機能です。

ポート番号を 3000 以外に変更する

server.js の PORT 定数を変更し、start.bat の start "" "http://localhost:3000" も同じ番号に合わせます。社内で 3000 が禁止されている場合のみ対応してください。

カテゴリやタグ機能を追加するには？

Posts テーブルに Category NVARCHAR(20) カラムを追加し、フォームに select を追加、検索 API にカテゴリフィルタを足します。正規化するなら Categories テーブルを別途作成する設計も議論題材になります。

画像投稿に対応できますか？

標準研修の範囲外です。実装するなら multer でファイルアップロード、保存先フォルダ、画像 URL を Message に保存する等が必要で、セキュリティ（ファイルタイプ検証、サイズ制限）の学習量が増えます。メンター判断でオプション課題に。

ユーザー認証（ログイン）を追加するには？

セッション + Cookie、JWT、Windows 統合認証など選択肢があります。研修の延長として「固定の研修用パスワード1つ」から始める簡易版も可能ですが、工数が大きいため発表後の個人課題向きです。
